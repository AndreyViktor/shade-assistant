# T060 — Resultados estruturados ao vivo com evidências

## Escopo entregue

- Structured Output v2 combina cartões e operações de resultados sem chamada adicional.
- Store em memória resolve referências do modelo contra falas finais do contexto enviado e deriva localmente fonte, trecho e horários.
- Painel mostra tópico, decisões, ações, perguntas e riscos; cada item diferencia fato/inferência e abre suas falas de suporte.
- IPC de sessão v9 transporta snapshot estrito; lifecycle preserva resultados na pausa e limpa ao parar, revogar, falhar, recarregar ou reiniciar.
- Consentimento informa o envio periódico de falas finais, resumo, resultados atuais e contexto opcional. Não houve API paga, captura real, nova permissão ou persistência.

Política, limites e alternativas: [ADR 0027](../../adr/0027-live-structured-results.md).

## Critérios exercitados

| Critério                | Evidência automatizada                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------------------------- |
| Conteúdo ausente        | Resposta sem operações mantém estado vazio e não cria item.                                             |
| Evidência inválida      | Referência inexistente é ignorada; o IPC rejeita snapshots fora dos limites.                            |
| Contradição/remoção     | Remoção só atua sobre chave/tipo existente com nova fala final de suporte.                              |
| Revisão/correção        | Upsert da mesma chave/tipo substitui texto/evidências; mudança de tipo é rejeitada.                     |
| Fato vs. inferência     | Decisões inferidas são inválidas; UI rotula “Fato da reunião” ou “Inferência a confirmar”.              |
| Fala/horário            | O store copia fonte, `startMs`, `endMs` e trecho do contexto local; a UI exibe fonte, intervalo e fala. |
| Consentimento/lifecycle | Testes verificam disclosure, pausa com preservação e limpeza por revogação/parada.                      |
| Integração              | Fixture sintética cobre evento nativo → contexto → Responses mock → store → IPC → UI, sem rede.         |

## Testes e gates

- Testes focados de contrato, store, provider, pipeline, IPC e React no Node 26: **179/179 aprovados**.
- `npm run verify`: lint, formato, tipos e build aprovados; Vitest com **924 aprovados e 19 skipped**; runner com **19/19 aprovados**.
- `npm run test:smoke`, com Electron fora do sandbox e fixtures offline: **27/28 aprovados** na execução completa. Todos os fluxos T060 passaram; o único caso restante foi o teste histórico não alterado `tests/e2e/panel.spec.ts`, inicialmente sem foco nativo no macOS.
- Reexecução isolada de `panel.spec.ts` com uma única ativação nativa da janela no momento em que o processo Electron surgiu: **1/1 aprovado**, incluindo foco, minimizar/restaurar, zoom e reabertura. A cobertura combinada aprovou todos os 28 casos sem modificar ou desabilitar o teste.
- `git diff --check`: aprovado.

## Encerramento

T060 concluída. O smoke precisou ser dividido por causa da política de foco do macOS nesta sessão gráfica, mas todos os casos foram executados e aprovados; nenhum gate foi removido ou enfraquecido.

## Limites

- Fixtures são sintéticas e o transporte é mockado; não medem a qualidade semântica de uma reunião real nem fazem chamada paga.
- Referência válida prova que existe fala de suporte, não que a interpretação do modelo é necessariamente correta.
- Resultados são temporários e não podem ser confirmados/editados/exportados nesta tarefa; ações revisáveis continuam em T066.
- O store mantém no máximo 17 itens e não tenta fundir semanticamente chaves diferentes.
- O smoke usa fixtures offline e não avalia captura real, reunião real ou API paga.
